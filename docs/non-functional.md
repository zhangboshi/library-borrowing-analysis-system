# 性能与安全设计

## 性能/容量
- **读写分离**：查询走分析库或只读副本，写入走主库；BI 查询与在线接口解耦。
- **缓存策略**：热门榜单、分馆统计使用 Redis 缓存（TTL 5~15 分钟）；命中率不足时回落到物化视图；对用户查询采用 user-scoped 缓存键。
- **分页与限流**：接口默认限制返回条目（示例为 50/500 上限），对高频接口配置令牌桶限流（如 100 RPS/实例）。
- **批/流结合**：每日批处理生成宽表，流处理用于实时活跃借阅和逾期提醒。
- **异步 IO**：FastAPI + async ORM/驱动（asyncpg/httpx）减少等待时间；批任务使用队列解耦。
- **可伸缩性**：水平扩展 API 副本；使用 HPA 基于 CPU/p95 latency 扩容；作业队列根据 backlog 长度自动扩缩。

## 安全
- **身份认证**：面向 API 的 JWT/OAuth2；对后台管理接口启用 MFA；演示服务可用 API Key 头（如 `X-API-Key`）。
- **授权**：RBAC 控制敏感维度（用户明细、费用数据）；细粒度行级权限（按分馆/城市）。
- **传输安全**：全站 HTTPS，HSTS，TLS 1.2+；禁止弱密码套件。
- **数据保护**：敏感字段（用户信息、费用）加密存储，日志脱敏；备份加密存放，最小化保留周期。
- **审计与合规**：所有写操作与管理动作记录审计日志；保留足够时间以满足合规（如 180 天）。

## 可观测性与运维
- **指标**：QPS、p95 延迟、错误率、缓存命中率、物化视图延迟、消费滞后（流处理）。
- **日志**：结构化 JSON 日志，包含 trace_id / user_id / branch；错误日志区分 4xx 与 5xx。
- **追踪**：OpenTelemetry 采样；跨 API/数据库/缓存链路注入 trace context。
- **报警**：SLO 触发（可用率、延迟、数据新鲜度），并设置自动降级路径。
